Behavior programs that know how likely they are.

metis is a small language, LLP, in which a program is a catalog of typed, weighted rules — and denotes a probability measure over its own runs. A certified runtime evaluates it exactly in milliseconds; a human-gated loop grows it; a small local model speaks for it.

Read the paper See the code
world → program → surprise → gated change → catalog → the device's words.

This is the purpose in one loop: the device's behaviour is a file people can read and approve, and it improves without retraining a model. (Rule names from domains/plant/plant.llp; the new rule and its words from domains/plant/extensions/visitor.llp, metis-catalog.)

Three layers, three papers

Layer 1 — the language

LLP: typed, staged, weighted linear-logic rules, read three ways at once — as proofs, as runs, as a measure.

The OCaml compiler metisc, the Python referee metispy, a header-only C++ runtime; exact parity at 10-9 across 200+ gates; a Lean 4 mechanization of the core theorems.

Paper: Behavior Programs as Measures over Proofs (draft 0.3, 2026-09-30)
metis-lang · metispy
Layer 2 — the catalog and the loop

A program becomes a package: one directory, one manifest, one loader, built and run by both toolchains in CI.

An agentic loop turns prose or a seed program into a package, exercises it against a simulated world, and proposes extensions — every write a diff a person approves. 28 packages today: story worlds, puzzles, planning, device domains, eight IPPC/RDDL worlds against pyRDDLGym.

Paper: Behavior Catalogs in Practice (draft, in preparation)
metis-catalog · metis-loop · metis-agentic-loop
Layer 3 — the agent

A small local model (Gemma 4 E2B, ~2 GB) does not own the device's state, procedure or safety; the runtime does.

The model maps an utterance to one typed intent, narrates, proposes, asks. Two agents share one kernel; the device gets smarter by catalog changes, never by retraining. A Python dev stack and a Go embedded runtime, at parity on recorded days.

Paper: Small Models, Certified Behavior (draft, in preparation)

A fragment of formalization

catalog plant 1.
provenance text "a potted plant that dries out: the person waters it or asks how it is" "2026-10-15".
layers (dyn).
stages (main).
…
pred moist : plant.
pred dry : plant.
…
pred visitor : plant.        % the world's report: someone came by (the host, or the person's World tab)

stage main {
  %% The sun has been on me for a while; my soil dries out.
  dry_out [dyn] : moist * sun -o dry.
  %% When I am dry and you water me, my soil is moist again.
  water [dyn] : dry * cmd_water -o moist * done(water).
  …
}

A rule is a linear-logic clause with a weight; %% lines are what the agent says about it. From metis-catalog/domains/plant/plant.llp, verbatim; … marks lines left out.

catalog plant 1. — the header: a catalog has a name and a version; the loader lists it, CI builds it.
pred moist : plant. — a typed predicate: atoms are resources in a multiset, counted, not just true or false.
moist * sun -o dry — the rule: a linear implication. What is on the left is consumed, what is on the right is produced; $ marks a premise only read. A weight on a rule, or a weight port bound by the host, prices its choice.

The same file is what metisc compiles, what the REPL runs, what CI replays against a committed trace, and what the agent narrates from.

The loop, as a gate

proposal plant: extension visitor — a visitor who waters the plant
--- a/domains/plant/extensions/visitor.llp
+++ b/domains/plant/extensions/visitor.llp
@@ -0,0 +1,6 @@
+catalog visitor 1.
+extends plant.
+stage main {
+ %% A visitor has watered me; my soil is moist again.
+ visitor_waters [dyn] : dry * visitor -o moist.
+}
approve? [y/n] y
written domains/plant/extensions/visitor.llp (new)

Every change to a catalog is a diff a person reads. Six story programs were ported this way for 0.06 USD, each program byte-equal to its seed (one with a one-line comment change the person asked for). The diff above is the loop SDK's own dry run of plant's extensions/visitor.llp (python -m metis_loop_sdk.catalog apply … --dry-run); the proposal and approval lines are the gate's shape in the console.
